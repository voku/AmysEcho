From the NG-2 reviews: exercise the IndexedDB adapter in the real browser (round trip, onblocked, onversionchange, prefix range, private mode, one large transaction); until then it must not be wired to real data. From the NG-25 reviews, verify in a real browser: the usage record is read and written in separate transactions, so two tabs can make it drift; a read (export, usage) can recreate the usage key of a profile another tab removed; an export racing a removal can return a document with no data and no error; quota failures surface as a generic Error, not a typed one; a restore is one transaction with up to 10,000 puts; the best-effort usage correction swallows every rejection but not a synchronous throw. Decide whether read-modify-write moves into one IndexedDB transaction or behind Web Locks.
