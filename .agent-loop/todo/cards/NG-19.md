## Agent Task Brief
Goal: gesture examples are stored per profile as a versioned record (profile id, concept id, capture time, extraction version, anchor, features stored unweighted or with their extraction parameters), included in export/restore and removed completely on profile delete. Incompatible versions are rejected, never guessed. Decide and document whether raw landmarks are kept on the device to allow re-extraction; if yes, say so in the caregiver area. Scope: src/recognition/, src/profiles/, test/, docs/storage.md, docs/recognition.md. Depends on: NG-2. NG-8 item 5, product contract section 3. From the NG-2 reviews: volume is fine (300 examples gave a 17 MB export handled in under a second in memory), but one IndexedDB transaction of that size is untested; values are JSON only. From the NG-25 reviews: one 32x86 example is about 54.5 kB at full double precision and about 20.5 kB rounded to four decimals, so the 64 MiB profile limit holds about 1,230 or about 3,280 examples; decide precision and examples per concept, and store one data name per example (appending to one large value costs about 100 ms per write at 2.3 MB in Node). Float32Array is rejected by cloneJson and must be converted. usage() reads the whole profile and a refused growing set recounts it (about 300 ms on a 63 MiB profile in Node): call usage() when a teaching session opens, warn well before the limit, and never retry a refused write in a loop. OWNER REQUIREMENT 2026-11-22 (Lars Moelleken): after the open UI tasks are done, gesture recognition must work properly with one hand and with two hands. Treat both as first-class: the tracker choice, capture, segmentation, features, teaching and the evaluation must each be shown to work for one-handed and for two-handed gestures, including a hand that leaves or enters the frame and the hands swapping sides; report measured numbers for both groups separately and never tune a threshold to pass.
